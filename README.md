# Bitrix-24 — Командный проект (MVP Интерактивной доски)

Репозиторий разработки веб-приложения с интерактивными досками, стикерами и совместной работой.

## 📂 Структура проекта

* `client/` — Frontend-приложение (React, TypeScript, HTML, CSS).
* `server/` — Backend API (Node.js, Express, PostgreSQL).
* `qa/` — Тест-кейсы, коллекции Postman и документация по тестированию.
* `docker-compose.yml` — Конфигурация для быстрого локального запуска базы данных PostgreSQL.

---

## 🚀 Быстрый старт (Локальный запуск)

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd Bitrix-24
git checkout dev
```

### 2. Запуск базы данных (PostgreSQL)
Для разработки не нужно устанавливать PostgreSQL вручную на компьютер. Убедитесь, что у вас запущен **Docker Desktop**, и выполните в корне проекта:
```bash
docker-compose up -d
```
База данных поднимется на порту `5432`.
* **Строка подключения (`DATABASE_URL`):** `postgresql://admin:rootpassword@localhost:5432/bitrix24_mvp`
* **Остановить БД:** `docker-compose down`

### 3. Запуск Backend и Frontend
* **Backend:** перейдите в папку `server/`, создайте файл `.env` по образцу `.env.example`, установите зависимости (`npm install`) и запустите сервер.
* **Frontend:** перейдите в папку `client/`, установите зависимости (`npm install`) и запустите проект.

## 🛠 Правила работы с Git (Обязательно для всех!)

В репозитории настроена защита веток **`main`** и **`dev`**. Прямой `git push` в эти ветки заблокирован.

1. **Актуализируйте ветку `dev` перед новой задачей:**
   ```bash
   git checkout dev
   git pull origin dev
   ```

2. **Создайте свою ветку под задачу:**
   ```bash
   git checkout -b feat/название-задачи
   ```
   *(Примеры названий: `feat/auth-jwt`, `feat/board-canvas`, `fix/login-validation`)*

3. **Пишите код только в своей директории:**
   * Фронтенд-разработчики работают в `client/`.
   * Бэкенд-разработчики работают в `server/`.

4. **Не загружайте секреты:**
   * Файлы `.env` и папка `node_modules` добавлены в `.gitignore`. Если добавляете новые переменные окружения, обязательно прописывайте их без паролей в `.env.example`.

5. **Сдача задачи (Pull Request):**
   * Отправьте свою ветку на GitHub:
     ```bash
     git push -u origin feat/название-задачи
     ```
   * Перейдите на GitHub во вкладку **Pull requests** -> **New pull request**.
   * Выберите слияние **в ветку `dev`** (`base: dev <- compare: ваша-ветка`).
   * Дождитесь проверки (Approve) от тимлида или QA, после чего ветка будет влита в `dev`.
